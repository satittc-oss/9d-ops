# 9d-ops
9D Integrated Operations - Nine Distribution (Microsoft 365 sign-in required)

## ออกเวอร์ชันใหม่
เมื่อเปลี่ยน `M_VER` ใน `index.html` ให้แก้ `version.json` เป็นเลขเดียวกันเสมอ — หน้าเว็บที่เปิดค้างไว้ใช้ไฟล์นี้เช็คว่ามีเวอร์ชันใหม่
ถ้าแก้ไอคอนหรือ manifest ให้เปลี่ยนชื่อ cache (`C`) ใน `sw.js` ด้วย

## หน้าเมืองจำลอง (v16.14)
`city.html` คือฉาก 3 มิติ (ฝังในเมนู "เมืองจำลอง" ผ่าน iframe `city.html?embed=1`) และใช้ `vendor/three.r128.min.js` (three.js r128, MIT) — ตอนนี้ยังใช้ข้อมูลจำลอง ยังไม่ผูกกับโครงการจริง

## ข้อมูลจริงในเมืองจำลอง + Outlook (v16.15)
- หน้าเมืองจำลองส่งข้อมูลโครงการจริง (จาก All Projects List + 9D Project Tracking) เข้า `city.html` ผ่าน `postMessage` — 1 โครงการ = 1 คัน: รออนุมัติ → Sales · กำลังทำ → Engineering (โต๊ะของ Engineer ผู้รับผิดชอบ) · ส่งงานแล้ว → กลุ่มลูกค้า · WIN / LOSS / ยกเลิก (14 วันล่าสุด) → ลานผลงาน
- "เชื่อมต่อ Outlook" ขอสิทธิ์ `Mail.Read` + `Calendars.Read` (อ่านเฉพาะ /me ของคนที่ล็อกอิน) แยกจากการล็อกอินปกติ — เนื้อหาเมล/ปฏิทินอยู่ในหน่วยความจำของหน้าเว็บเท่านั้น
- ตำแหน่งงานของ Engineer จากปฏิทิน (ช่วงเวลา + รหัสตึก ไม่มีหัวข้อ) บันทึกเป็นแถว `presence:<email>` ใน 9D Project Tracking (`ProjectItemId = -9000000000`) ถ้าเจ้าตัวไม่ปิดการแชร์
- กฎจับคู่หัวข้อนัดหมาย → ตึก อยู่ใน `OL_RULES` ของ `index.html`


## ขั้นตอนย่อยระหว่าง "กำลังทำ" (v16.16)
- พิมพ์ใน Teams Channel ของโครงการ: `#รับงาน` · `#ทำBOM` · `#รอซัพ` · `#รอจัดซื้อ` · `#รอราคา` · `#รอลูกค้า` · `#รอเซลส์` · `#ส่งราคา` (หรือเลือกจากเมนู "ตั้งขั้นตอน…" ในหน้าสถานะโครงการ) — Engineer หรือเซลส์เจ้าของงานใช้ได้
- บันทึกเป็นแถวเพิ่มใน 9D Project Tracking (`ProjectItemId` ติดลบ, Payload `{sub,at,by,...}`) ใช้ตัวล่าสุด และใช้ได้จนกว่าสถานะหลักจะเปลี่ยน (#ส่งงานแล้ว ฯลฯ)
- ค้างเกินกำหนด (`SUBST[*].warn`: ของเรา 3 วัน · ซัพ/จัดซื้อ/ราคา/เซลส์ 7 วัน · ลูกค้า/ส่งราคา 14 วัน) ระบบเตือนใน Channel ครั้งเดียวต่อขั้นตอน
- เมืองจำลอง: รถของงานไปจอดที่ตึกของคนที่ถืองานอยู่ (Supplier / จัดซื้อ / ลูกค้า / Sales)
- คำสั่งจาก Teams จะถูกประมวลผลเมื่อ Engineer เปิดเว็บแอป (ซิงค์ Teams)

## บอร์ดสถานะ · คอลัมน์ขั้นตอนใน SharePoint · Power Automate (v16.17)
- หน้าสถานะโครงการ: ทุกงานที่กำลังทำมีช่อง "ขั้นตอน" (ยังไม่ระบุ / รอราคา ฯลฯ) และสลับมุมมอง **รายการ / บอร์ด** ได้ (บอร์ด = คอลัมน์ตามขั้นตอน)
- All Projects List: คอลัมน์ `NineDStep` ("ขั้นตอนงาน (9D)") สร้างอัตโนมัติเมื่อ Admin/ผู้อนุมัติเปิดเว็บ แล้วเขียนข้อความขั้นตอนทีละ 25 รายการต่อรอบ
- เมืองจำลอง: แท็บ "ทีมงาน" แสดงชื่อแต่ละคน + กำลังทำอะไร + งานในมือ · มิเตอร์ "งานที่ Engineering" (ไม่มีเพดาน 40 แล้ว)
- Power Automate: เว็บเขียนแถว `flow-index` (ProjectItemId -9100000000) = Channel ที่ต้องอ่าน; flow เขียนแถว `inbox:<id>` (ProjectItemId -9200000000) เก็บข้อความล่าสุดของแต่ละ Channel; เว็บแปลง #แฮชแท็กจาก inbox ด้วยกติกาเดียวกัน แล้วเขียนเป็นบันทึกถาวรเมื่อ Engineer เปิดเว็บ

## รับงาน = อนุมัติ · เมนูสถานะเดียว · กล่อง "งานอยู่ขั้นไหน" (v16.18)
- งานที่อนุมัติแล้วเป็น "รับงานแล้ว · กำลังดำเนินการ" อัตโนมัติ (ไม่มี #รับงาน แล้ว) — ขั้นตอนอื่นตั้งต่อจากนี้
- แต่ละโครงการมีเมนู "เปลี่ยนสถานะ / ขั้นตอน…" เดียว: ขั้นตอน · ส่งงานแล้ว · ปิด WIN / LOSS / ยกเลิก · เปิดงานใหม่
- กล่อง "งานอยู่ขั้นไหน" นับงานแต่ละขั้น กดเพื่อกรองรายการ
- หน้าโครงการทั้งหมด: เอากระดานเดิมออก เหลือปุ่มไปบอร์ดในหน้าสถานะโครงการ

## ตรวจข้อมูลงานเก่า (v16.19)
- หน้าสถานะโครงการ (Admin / ผู้อนุมัติ): ปุ่ม "ตรวจข้อมูลงานเก่า" อ่านประวัติเวอร์ชันของแต่ละรายการใน All Projects List (`/_api/web/lists(guid)/items(id)/versions`) หาว่าใครเปลี่ยน Request Status / Approval status เป็นอนุมัติครั้งแรก + ดาวน์โหลด CSV
- ปุ่ม "ตั้ง N งานเป็น อนุมัติแล้ว · กำลังดำเนินการ": Request Status = Approved · สถานะล่าสุด = In Progress · แพ้/ชนะ = Process · ขั้นตอนงาน (9D) = รับงานแล้ว · กำลังดำเนินการ (ข้ามงานที่ส่งงาน/ปิด/ไม่อนุมัติ) และบันทึกผู้อนุมัติที่พบลงประวัติการอนุมัติของเว็บ

## ซิงค์ Teams ไม่ต้องเริ่มใหม่ทุกครั้ง (v16.21)
- ผลซิงค์ Teams เก็บใน IndexedDB ของเครื่อง (ฐาน `9d-ops`, คีย์ `ts:<oid ของผู้ใช้>`) — เปิดแอป/เว็บใหม่แสดงข้อมูลชุดล่าสุดทันที (ถ้าอายุ < 10 นาทีไม่ซิงค์ซ้ำ, เก็บได้ 7 วัน) · ออกจากระบบ = ลบฐานนี้
- อัปเดตแบบเพิ่มเฉพาะส่วนที่เปลี่ยน: Channel ที่เคยอ่านแล้วเช็ก `messages?$top=1&$expand=replies` (ลายเซ็น = id บทสนทนาล่าสุด + จำนวน reply + เวลาแก้ล่าสุด) ถ้าเหมือนเดิมใช้ผลเดิม · อ่านเต็ม (สูงสุด 200 โพสต์) เมื่อมีข้อความใหม่ หรือครบรอบอ่านเต็ม 6–24 ชม. (สุ่มกระจาย, ครั้งละ ≤ 40 Channel)
- ระหว่างอัปเดต ป้ายบนแดชบอร์ดแสดง "อัปเดต Teams x/y · แสดงข้อมูลเมื่อ …" และตัวเลขเป็นของชุดเดิมจนอัปเดตเสร็จ

- หน้าสถานะโครงการ: ตัวเลขด้านบนเป็นแถบสถานะ — "กำลังทำ" แตกเป็น 8 ขั้นตอน (สีประจำขั้น `STEPCOL`) + หลังส่งงาน (ส่งงานแล้ว / ปิดแล้ว) กดเพื่อกรอง

- เมืองจำลอง: สีรถตามเซลส์ (แท็บ "เซลส์") · เซลส์เห็นงานของเซลส์คนอื่นเป็นรถสีเทาไม่มีชื่อโครงการ (นับรวมในภาระงาน Engineer) · ปุ่มขยายเต็มจอ
