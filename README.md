## v16.42 · ชื่อขั้นตอน/สถานะใช้ค่ากลางชุดเดียว (เว็บ · Teams · SharePoint)
- ชื่อการ์ดและผู้รับผิดชอบที่ Admin ตั้งในหน้า "สถานะโครงการ" (`uiConfig.status.cards`) ถูกนำไปใช้กับ **ข้อความ Teams ที่ส่งใหม่** และคอลัมน์ "ขั้นตอนงาน (9D)" ใน All Projects List ให้ตรงกับที่แสดงบนหน้าเว็บ (เดิม Teams ใช้ชื่อคงที่ เช่น เว็บ "ประสานจัดซื้อ (รอราคาทุน)" แต่ Teams เขียน "ประสานจัดซื้อ")
- ใช้ตัวแปลค่ากลางชุดเดียวทั้งโหมดเดิมและโหมดคิวใหม่ รวมเบราว์เซอร์และ Node worker: `mCardName`/`mPStatName` ใน index.html, `cardView(settings)` ใน sync-m365.js
- **รหัสสถานะ/ขั้นตอน กฎสิทธิ์ และการอ่านคำสั่ง #แฮชแท็ก ยังมาจาก `SUBST`/`SUBORD`/`PSTAT`/`STATUS`/`STEPS` เสมอ** ข้อความที่ Admin กรอกเป็นเพียงชื่อที่แสดง (escape + จำกัด 80 ตัวอักษร ค่าที่ผิดรูป/ยาวเกินจะ fallback เป็นค่าเริ่มต้น) ไม่เปลี่ยนเป็นรหัสหรือกฎ
- ไม่แก้ข้อความ Teams เก่าย้อนหลัง · ลำดับการ์ดที่ Admin เผยแพร่ไว้ยังคงเดิม ไม่เขียนทับเงียบ ๆ

## v16.40 · Admin ปรับหน้าสถานะ / กรอง Engineer และเซลส์
- หน้าสถานะมีปุ่ม **ปรับแต่งหน้านี้** สำหรับ Admin → ศูนย์ผู้ดูแล / สถานะโครงการ: แก้หัวข้อ คำอธิบาย ชื่อการ์ด และข้อความ “อยู่ที่” พร้อมเลื่อนลำดับภายในกลุ่มระหว่างทำ/หลังส่งงาน มีตัวอย่างในร่างก่อนกดเผยแพร่ให้ทั้งทีม
- คำและลำดับเป็นการแสดงผลเฉพาะหน้าสถานะ รวมบอร์ดและชื่อขั้นตอนในรายการ รหัสขั้นตอน/การอนุมัติ/แฮชแท็ก Teams และผู้รับผิดชอบจริงยังใช้ข้อมูลเดิม
- เพิ่มตัวกรอง **Engineer ผู้รับผิดชอบ** และ **เซลส์เจ้าของโครงการ** เลือกพร้อมกันได้ ยอดการ์ด รายการ บอร์ด และประวัติในหน้านี้กรองจากโครงการชุดเดียวกัน; ค้นหา Engineer ได้และคงการแบ่งแสดงชุดละ 200 งาน
- รายชื่อในตัวกรองมาจากโครงการที่บัญชีเข้าถึงได้เท่านั้น มีตัวเลือก “ยังไม่ระบุ Engineer” เมื่องานยังไม่กำหนดผู้รับผิดชอบ และล้างตัวกรองชื่อได้โดยคงคำค้น/กลุ่มสถานะไว้
- `uiConfig` รุ่น 2 เก็บรูปแบบหน้าสถานะร่วมกับ UI เดิม อ่าน/นำเข้ารุ่น 1 ได้ พร้อมสำรองฉบับก่อนหน้า ส่งออก/นำเข้า และกันร่างเก่าทับค่าที่ Admin อีกคนแก้
- ตรวจด้วยข้อมูลจำลองเท่านั้น รวมโครงการ 2,000 งาน การค้นหา/ตัวกรองร่วม สิทธิ์ตามบทบาท การบันทึกตั้งค่า และหน้าจอมือถือ ไม่มีการแก้ข้อมูลหรือสิทธิ์ใน Microsoft 365 ระหว่างพัฒนา

## v16.39 · ปุ่มรูปแบบใหม่ / เปิดรายการ Channel จากหน้ารออนุมัติ
- ปรับปุ่มคำสั่งเป็นขอบบาง มุมมน และเงาเบา แยกปุ่มหลักกับปุ่มรองให้ชัด รวมปุ่มในฟอร์มคำขอ/นำเข้าเดิมที่ยังมีขนาดใหญ่ คงขนาดกระชับ 32px และพื้นที่แตะมือถือ 44px
- ตัวเลือกธีมเปลี่ยนเป็นตัวอย่างชุดสี 3 แถบ มีเครื่องหมายถูกและพื้นหลังอ่อนเมื่อเลือก เอากรอบเลือกซ้อนออก ส่วนเส้น focus ยังคงแสดงเมื่อใช้คีย์บอร์ด
- **ยกเลิก Popup อัตโนมัติหลังซิงค์ Teams** เพิ่มปุ่ม **นำโครงการจาก Teams** พร้อมจำนวน Channel ในหน้ารออนุมัติสำหรับ Engineer/Admin กดเองจึงเปิดรายการ การซิงค์อัปเดตเฉพาะจำนวนบนปุ่ม
- รายการนำเข้าค้นหาชื่อ Channel/Team/รหัส แบ่งหน้าละ 25 รายการ ซิงค์ด้วยปุ่ม และแสดงสถานะเมื่อไม่พบรายการได้ กดตรวจทีละ Channel แล้วใช้ขั้นตอนยืนยันสร้าง SharePoint เดิม ยังคงกันรายการซ้ำและไม่สร้าง Channel ใหม่
- ทดสอบ `node --test tests/*.test.cjs` ผ่าน 116 กรณี รวมไม่มี Popup เมื่อเรียกอัตโนมัติ/บทบาทไม่รองรับ กันคลิกซ้อน และค้นหารายการ; ตรวจ UI ด้วยข้อมูลจำลองบนคอมพิวเตอร์และมือถือ ตัวอย่าง `?role=admin&orphans=28` สำหรับทดสอบแบ่งหน้า ไม่มีการเขียนข้อมูลจริงขององค์กรระหว่างพัฒนา

## v16.38 · ปุ่มกระชับ / ศูนย์ผู้ดูแล / ธีมและหน้า / จัดการผู้ใช้
- ปุ่มคำสั่งหลักในแดชบอร์ด ทะเบียน สถานะ ใบยืม ใบเสนอราคา งานเซอร์วิส หน้าตั้งค่าเดิม และ Dialog ใช้ขนาด/มุม/รูปแบบร่วมกัน: คอมพิวเตอร์ 32px (เลือก 36px ได้), มือถือพื้นที่แตะอย่างน้อย 44px และช่องกรอก 16px; การ์ดข้อมูลและเมนูนำทางคงพื้นที่อ่านรายละเอียด
- **ศูนย์ผู้ดูแล** เป็นเมนูเฉพาะ Admin แยก 5 ส่วน: ธีม · หน้าและเมนู · ปุ่มคำสั่ง · ผู้ใช้ · ระบบ / สำรอง บัญชีบทบาทอื่นเข้าแผงนี้ไม่ได้ และการบันทึกตรวจบทบาท Admin จากค่ากลางล่าสุดอีกครั้ง
- ธีมมี 4 ชุดสี หรือเลือกสีหลักเอง ปรับความกระชับ มุมปุ่ม และพื้นหลังได้ ทดลองบนหน้าจอ Admin ก่อนเผยแพร่ให้ทีม; ร่างธีม/หน้า/ปุ่มอยู่ในหน่วยความจำของแท็บจนกดเผยแพร่หรือรีโหลด
- เปิด/ปิดหน้า เลือกบทบาทที่เห็น เลื่อนลำดับเมนู และเพิ่ม **หน้าข้อมูล/ลิงก์** ได้สูงสุด 12 หน้า หน้าละ 6 ปุ่มลิงก์ HTTPS เนื้อหาเป็นข้อความธรรมดา ไม่มีการรัน HTML/JavaScript ที่กรอก การเพิ่มกระบวนการงานหรือฐานข้อมูลชนิดใหม่ยังต้องพัฒนาโค้ด
- ซ่อน/แสดงคำสั่งเสริม 13 กลุ่ม เช่น สร้างคำขอ, CSV, Archive, เปิดงานใหม่, ลบ และคำสั่งใบเสนอราคา; เป็นการจัดหน้าจอเท่านั้น ไม่ใช่การเปลี่ยนสิทธิ์ข้อมูล ปุ่มบันทึก/ยกเลิก/ตั้งสิทธิ์และทางเข้า Admin คงใช้ได้ หน้าและเมนูยังอยู่ใต้ข้อกำหนดบทบาทเดิม
- รายชื่อผู้ใช้ค้นหาและแบ่งหน้าครั้งละ 25 คน เพิ่ม/แก้ชื่อและบทบาทในแอปได้ การเพิ่ม Admin ต้องติ๊กยืนยัน และลดบทบาท Admin ของตัวเองไม่ได้; ไม่เพิ่มสิทธิ์ SharePoint/Teams โดยอัตโนมัติ หลังเพิ่ม Admin ให้ผู้ดูแลตั้งค่าสิทธิ์ใบเสนอราคาอีกครั้งตามขั้นตอน v16.37
- การบันทึกจากศูนย์ผู้ดูแลอ่าน settings ล่าสุด, คิวงานในแท็บ/Web Locks ข้ามแท็บที่รองรับ, ส่ง [`If-Match` eTag](https://learn.microsoft.com/en-us/graph/api/listitem-update?view=graph-rest-1.0) และตรวจร่างเก่าก่อนเขียน เมื่อค่าหน้าจอถูก Admin อื่นเปลี่ยนจะแจ้งและเก็บร่างไว้ ไม่ retry PATCH ที่ไม่ทราบผลจนเสี่ยงทับข้อมูล; ตรวจ Payload ซ้ำเพื่อยืนยันเมื่อเครือข่ายขาดหลังเขียน
- ส่งออก/นำเข้า JSON เฉพาะธีม หน้า ลำดับและปุ่ม (ไม่รวมรายชื่อผู้ใช้/โครงการ/การเชื่อมต่อ), เก็บค่าหน้าจอก่อนหน้า 1 ฉบับ และประวัติการเปลี่ยนค่าล่าสุด 12 รายการ การนำเข้า/คืนค่าเป็นร่างก่อนเผยแพร่
- ใช้ settings แถวเดิม `ProjectItemId=0` ไม่เพิ่ม List/คอลัมน์ ฟิลด์ใหม่คือ `uiConfig` (schema 1), `uiRevision`, `uiUpdated`, `uiPrevious`, `uiAudit`; จำกัด UI config 16,000 bytes, settings รวม 62,000 bytes และแสดงพื้นที่ใช้ในหน้าระบบ รายชื่อยังโหลดจาก settings เดิม การแบ่งหน้าช่วยลด DOM แต่ถ้าทีมมีจำนวนมากจนใกล้ขีดจำกัดควรแยกทะเบียนผู้ใช้/เชื่อม directory ในงานถัดไป
- ตรวจ syntax และชุดทดสอบจำลอง 112 กรณี รวมการชนกันของ Admin, eTag, ผลเขียนไม่แน่นอน, บทบาท, ไฟล์นำเข้าและการคงค่าตั้งค่าเดิม; ตรวจ UI บนคอมพิวเตอร์ 1280px/มือถือ 390px ด้วยข้อมูลจำลอง 360 โครงการและผู้ใช้ 121 คน ไม่ติดต่อ tenant จริง

## v16.37 · โลโก้โปร่งใส / Archive Channel / กราฟ / เมนู / ใบเสนอราคาทุกบทบาท
- โลโก้ Sidebar และหน้า Microsoft 365 ใช้ `assets/nine-logo.png` โปร่งใสจากภาพต้นฉบับ เอากรอบขาวออก; ตัวหนังสือโลโก้ใน Sidebar สีเข้มแสดงเป็นขาวด้วย CSS ส่วนไฟล์ภาพ/PDF คงต้นฉบับ และเก็บ PNG ใน PWA cache รุ่น 4
- ทะเบียนและหน้าสถานะโครงการ (รายการ/บอร์ด) มี **จัดเก็บ Channel** สำหรับงานปิด WIN/LOSS/ยกเลิกที่เชื่อม Teams แล้ว: Engineer/Admin ตรวจชื่อ Channel และกดยืนยันก่อนส่ง `POST /teams/{team-id}/channels/{channel-id}/archive` จริง
  - ขอ delegated `ChannelSettings.ReadWrite.All` เพิ่มผ่านปุ่ม Microsoft เมื่อจำเป็น ผู้ใช้ยังต้องมีสิทธิ์จริงใน Teams; เว็บไม่อนุมัติสิทธิ์ Microsoft แทนผู้ดูแล
  - บันทึก pending ก่อนส่ง, ไม่ retry POST อัตโนมัติ, กันกดซ้อนและอีกแท็บที่รองรับ Web Locks; HTTP 202 แปลว่ารอผล ต้องอ่าน `isArchived=true` ก่อนแสดงสำเร็จ หาก timeout ให้ตรวจผลเดิม/ตรวจใน Teams แล้วกดตรวจอีกครั้ง ไม่ส่งคำสั่งซ้ำ
  - ส่ง `shouldSetSpoSiteReadOnlyForMembers:false` จึงข้ามการตั้ง SharePoint site เป็น read-only; การเปิดโครงการใหม่ไม่คืนค่า Channel เอง ให้ unarchive ใน Teams ก่อนใช้สนทนา
- กราฟแดชบอร์ดมีพื้นที่ใต้เส้น จุด/ค่ากิจกรรมสูงสุด สรุปยอดรวมและค่าเฉลี่ย แถบอันดับหลายสี; อ่านรายละเอียดด้วยสัมผัส/เมาส์/คีย์บอร์ด และบอกว่าวันนี้ยังไม่สิ้นสุด ใช้ SVG ไม่เพิ่มไลบรารี
- Admin: **ตั้งค่า Workspace → จัดลำดับเมนูด้านข้าง** เลื่อนขึ้น/ลงหรือคืนลำดับเดิม เก็บร่วมกันทั้งทีมใน `settings.sidebarOrder` เมนูที่เห็นยังขึ้นกับบทบาท และภาพรวม/แถบมือถือยังทำงานเมื่อย้ายภาพรวมไปท้ายเมนู
- ปุ่ม **ดู/PDF · แชร์ · อีเมล · แก้ไข · ทำซ้ำ** ของใบเสนอราคาใช้รูปแบบเดียวกัน ปุ่มมือถือสูงอย่างน้อย 44px; เอกสารแชร์ยังมีเฉพาะข้อมูลลูกค้า ไม่รวมต้นทุน/กำไร
- ทุกบทบาทรวม Viewer สร้างและแก้ไขใบเสนอราคาของตนเองได้; Admin เห็น/จัดการทั้งหมด ใช้ Author จาก SharePoint และตรวจเจ้าของซ้ำก่อนเขียน พร้อม eTag ป้องกันทับข้อมูลที่ผู้อื่นเพิ่งแก้
